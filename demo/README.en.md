# demo — pipeline demo input and verification steps

For end-to-end smoke testing of translating a mixed-language `.docx` without breaking formatting, tables, TOC, or images.

## Demo input

| File | Contents |
| --- | --- |
| `mixed_language_sensor_manual.docx` | **A realistic sample.** An EN/DE mixed sensor manual (Japanese title + EN/DE paragraphs + a spec table + bullet lists). It carries **no `<w:lang>` tags**, so it **exercises the language-detection path directly**. Terms like `Authentication Token` / `API endpoint` / `Firmware` repeat, making it **ideal for testing glossary (term consistency)**. 32 segments, 12 table cells (picked up by recursive walking). |
| `glossary.sample.json` | A sample glossary for the above (target=ja). en/de term pairs under `bySource`. |
| other `*.docx` / `*.pdf` | Past translation outputs (for reference). |

> This sample was originally generated by a python-docx script (`create_sample.py`), but we decided to **bundle the produced docx as-is** (to avoid carrying a python-docx dependency and a "generation step nobody re-runs"). If you need the generation logic, see the git history.

## Prerequisite (build the dependency packages)

The pipeline consumes the **dist** of reader/translate/writer. Build them on first use and after updates.

```sh
for d in dtir-ooxml-reader-mcp dtir-ooxml-writer-mcp dtir-translate-mcp; do
  (cd ../../$d && npm run build)
done
```

## Verification commands (CLI = a-3 / b-3)

Run from the `dtir-docx-pipeline/` root.

### Translate with DeepL (a-3)

```sh
# Provide the key via your own environment variable. Free keys end with ":fx", Pro keys don't (auto-detected).
DEEPL_API_KEY='xxxx:fx' TARGET_LANG=ja \
  npx tsx src/cli.ts demo/mixed_language_sensor_manual.docx demo/manual.ja.docx
```

### Translate with a local LLM (b-3 / Ollama)

```sh
LLM_MODEL=tower-plus:9b LLM_BASE_URL=http://<host>:11434/v1 TARGET_LANG=ja \
  npx tsx src/cli.ts demo/mixed_language_sensor_manual.docx demo/manual.ja.docx
```

### Apply a glossary

```sh
# For LLMs it takes effect immediately via prompt injection. DeepL needs deeplIds (a pre-created glossary_id).
LLM_MODEL=tower-plus:9b LLM_BASE_URL=http://<host>:11434/v1 TARGET_LANG=ja \
GLOSSARY_PATH=demo/glossary.sample.json \
  npx tsx src/cli.ts demo/mixed_language_sensor_manual.docx demo/manual.ja.glossary.docx
```

### Preserve intra-paragraph formatting (de-collapse / runs mode)

```sh
# Preserve bold/color/links per run. Recommended with DeepL (tag_handling=xml).
# Paragraphs that fail to restore automatically fall back to collapse (fail-safe).
DEEPL_API_KEY='xxxx:fx' TARGET_LANG=ja INLINE_FORMATTING=runs \
  npx tsx src/cli.ts demo/mixed_language_sensor_manual.docx demo/manual.ja.runs.docx
```

## Structural machine verification (confirm nothing broke)

Run the translated docx back through the reader and confirm `validateDtir` is empty and the segment id set matches the original docx.

```sh
npx tsx src/verify.ts demo/manual.ja.docx demo/mixed_language_sensor_manual.docx
```

If you also want to check Word compatibility (PDF conversion via LibreOffice):

```sh
soffice --headless --convert-to pdf --outdir demo demo/manual.ja.docx
```

## Claude Desktop / MCP route (a-2 / b-2)

For conversational use, call the three MCPs in order (`docx_to_dtir` → `translate_dtir` → `dtir_to_docx`).
The docx is passed as base64 (`base64 -w0 demo/mixed_language_sensor_manual.docx`).
`translate_dtir`'s arguments let you switch `engine` (deepl/llm), `glossaryJson`, and `inlineFormatting:"runs"`.
See [`docs/cloud-llm-usage.en.md`](../docs/cloud-llm-usage.en.md) for details.
